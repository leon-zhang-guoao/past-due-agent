# Studio 1.2.0（2026-10-07）

提交 `b37ae109` · 镜像 `open-atlas-studio:1.2.0`

## 变化

- 新增**管理服务令牌**（[doc 112 §112.1](../../design/112-release-tool.md)）：发布工具 `atlas-pkg`
  以 `Authorization: Bearer <令牌>` 调用 Studio 接口，不经过登录。
  - 配置：`OPEN_ATLAS_STUDIO_ADMIN_TOKEN_SHA256` 写令牌的 **SHA-256**（小写 hex，可逗号分隔多个以便轮换）；
    `OPEN_ATLAS_STUDIO_ADMIN_TOKEN_USER` 写一个**已存在**的 workspace 管理员账号，令牌以它的身份行事。
    两个变量须同时设置，只设一个或格式不对时拒绝启动；都不设 = 功能关闭。
  - 生成：`openssl rand -hex 32` 得到令牌，`printf %s "$TOKEN" | shasum -a 256` 得到哈希；
    明文只放进发布工具的环境配置，哈希放进 Studio 配置。
  - 可达范围：`/api/studio/**` 的建模、数据源、凭证、发布、签发图 token 接口。**不能**：登录界面、账号与密码
    （`/api/studio/users`）、workspace 成员、Studio 管理员接口（`/api/studio/admin/`）、签发 workspace token。
    Bearer 请求不需要 CSRF 头。
  - 拒绝：令牌不对 → 401 finding `auth/admin-token-invalid`；指定账号不存在或已停用 → 拒绝并点名该变量。
  - 审计：每次调用记一条 `:auth/admin-token` 审计事件，actor 为 `service:admin-token`，带令牌哈希前 8 位。

## 在新环境里开启服务管理令牌

令牌与哈希**由新环境的管理员在本机生成**，发布包里不带任何预设值，也不要沿用其他机器上的值。只有用发布工具
`atlas-pkg` 时才需要；不开启时什么都不用做。

1. 生成令牌：`T=$(openssl rand -hex 32)`。
2. 计算 SHA-256：`printf %s "$T" | shasum -a 256`（Linux 上用 `sha256sum`），取前面 64 位十六进制。
3. 只把**哈希**写进 `config/studio.env`：`OPEN_ATLAS_STUDIO_ADMIN_TOKEN_SHA256=<哈希>`。同时设 `OPEN_ATLAS_STUDIO_ADMIN_TOKEN_USER=<本环境已存在的 workspace 管理员账号>`，两个变量缺一 Studio 拒绝启动。
4. 重启应用：`docker compose up -d --no-deps studio`。
5. 把**明文令牌**只交给发布工具：在运行 atlas-pkg 的 shell 里设置环境配置中 `admin_token_env` 指定的变量
   （例如 `export ATLAS_STUDIO_ADMIN_TOKEN="$T"`），不要写进任何文件或仓库。
6. 轮换：生成新令牌，把新旧两个哈希并排写（逗号分隔）并重启；发布工具换成新令牌后，删掉旧哈希再重启。
7. 关闭：把该变量留空（或注释掉）后重启；Studio 的 `OPEN_ATLAS_STUDIO_ADMIN_TOKEN_USER` 也一并留空。

## 组成

不适用（平台应用）。

## 契约

与 1.1.0 相同：提供 data-plane-api 1.1 · atlas-semantic 2.0.0 · artifact 1。

## 升级前提

无。用令牌时，`OPEN_ATLAS_STUDIO_ADMIN_TOKEN_USER` 指向的账号须先存在且是该 workspace 的管理员。

## 数据迁移

无。

## 升级步骤

部署目录 `.env` 中 `STUDIO_VERSION=1.2.0`（需要时在 `config/studio.env` 加上两个变量），
`docker compose up -d --no-deps studio`。

## 验收

- `/meta/contracts` 返回 `1.2.0`、`data-plane-api: 1.1`。
- 配置了令牌时，带令牌请求 `/api/studio/` 下的建模接口成功；请求 `/api/studio/users` 被拒；错误令牌得到 401。

## 回滚

镜像改回 `open-atlas-studio:1.1.0` 单独重启；无数据变化（1.1.0 忽略这两个变量）。

## 已知问题

池的变更记录（mutation / provenance）只记配置的账号（`OPEN_ATLAS_STUDIO_ADMIN_TOKEN_USER`），不记服务身份；
要知道某次变更是否由令牌发起，查同一时刻的 `:auth/admin-token` 审计事件（actor `service:admin-token`）。
