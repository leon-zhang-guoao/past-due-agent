# Studio 1.4.4（2026-10-10）

相对 [Studio 1.4.3](1.4.3.zh-CN.md)。数据面契约 data-plane-api **1.1 → 1.2，只增不改**；
既有 graph、已发布版本、制品文件、token 与客户端行为不变。设计与裁定见 open-atlas-docs 的
proposal `studio-saved-queries`。

## 新增

- **预定义查询（saved query）**：每个 graph 可保存带名字、描述、类型化参数（`?name` 只出现在值的位置）的 EQL。
  - Builder MCP：`list_saved_queries`、`save_saved_query`、`delete_saved_query`。保存前检查属性在草稿中存在，
    并用参数例子在草稿上真跑一次；失败即拒绝，返回与 `execute_eql` 相同的 finding。
  - 发布：预定义查询随下一版本发布，每个版本钉住自己的一套，回滚一起回。只改预定义查询也会产生新版本；
    若模型改动让某条查询引用的属性不存在，发布被拒并点名。
  - 数据面（data-plane-api 1.2）：MCP `list_saved_queries`、`run_saved_query`；`/eql` 接受
    `{:saved-query "<名字>" :params {...}}`。参数在服务端按类型校验后代入，返回形状与 `execute_eql` / `:request` 相同。
- **消费方最近请求（调试）**：Studio 记录发到已发布数据面的请求——每 graph 最近 50 条与最近 50 条失败（只在内存），
  钉住的保留 7 天（每 workspace 至多 200 条）；「capture failures 24h」规则自动钉住命中的失败请求。
  被拒绝的请求在 finding 上带 `:studio/recent-id`。记录不含结果数据；workspace 成员可见。
  Builder MCP 新增 `list_recent_queries`（默认看失败）。
- **Builder MCP instructions**：提示 agent 在查询反复出错或较复杂时，征得用户同意后保存为预定义查询。

## 界面

- 左上角与 Workbench 一致：Open Atlas 图标、`Open Atlas Studio`，版本号在名称下方（悬停可见 commit 与构建时间）；页脚不再显示版本。
- Query Studio：一个 **History** 面板，分 mine（本页在草稿上的运行）/ failed / consumers / pinned 四栏；
  工具栏改为 `History | Diagnostics` 切换、`explain`、`run query` 与 `⋯` 菜单（格式化、设为默认查询）。

## 兼容性

- 旧 graph 与 1.4.4 之前发布的版本没有预定义查询，`list_saved_queries` 返回空，无需迁移；制品三份文件不变。
- 两个新数据面工具只在 Studio 内嵌数据面挂载；独立 Server 不列出，`/eql` 收到 `:saved-query` 返回 `saved-query/unknown`。
- Builder MCP 工具由 31 条变为 35 条（Builder 28 + 数据面 7），只读 key 看不到 `save_saved_query` / `delete_saved_query`。

## 未包含

- workspace 的 graph 目录接口（描述、使用指南）。
- History 面板中的「另存为预定义查询」入口（目前由 agent 用 `save_saved_query` 完成）。
- graph 导出、复制时携带预定义查询；单个版本的回收。
