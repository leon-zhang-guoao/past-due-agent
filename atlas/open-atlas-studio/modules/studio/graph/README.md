# studio/graph — B5a

[B5a 的退出条件](../../../docs/design/80-build-plan.md)三条：

1. [scope projection v1](../../../docs/contracts/scope-projection-v1.md) **conformance 全过**
   ——闭包、混合 output、冲突与乱序输入均产生确定输出/错误；
2. **越界写留痕可查**；
3. **同一 graph 的并发 sync 合并为一次**（R3.7）。

## 裁定

### ① 治理数据住在池里，但不进 `as-dialect`

workspace 地盘、graph 菜谱、授权、越界写标记——都要跟着池导出导入，否则「删掉 store、
导入最后一次导出、精确重建」重建不出治理状态。

但它们**不是方言概念**：进 `as-dialect` 会让同一份模型因为「谁 own 它」不同而产出不同的
content-hash（[D4.3](../../../docs/design/40-artifacts.md#d43-三种身份分开content-hash-覆盖整份-contentedn)）。
B4.4 的确认记录已经立了这个先例，照它做：独立的 unique 键，不共用 `:pool.object/key`。

### ② 投影是**纯函数**，契约逐条实现，一条都不许省

[scope projection v1](../../../docs/contracts/scope-projection-v1.md) 有十步固定算法与一张
最低 conformance 矩阵。**那份契约是规格，不是参考**——「实现不得读取 latest、当前时间或池
快照之外的状态」这句话本身就是可测的。

矩阵最后一行是这一片的重心：**打乱池返回顺序、selector 顺序与引用顺序，输出字节及
content-hash 不变**。它挡的是「今天恰好排对了」——Datahike 的返回顺序、map 迭代顺序、
菜谱里引用的排列，任何一处泄漏进输出，这条都会红。

### ③ D3.14 的授权在**这一片**落地一半

授权判定的时点是**切版本**（[D3.14](../../../docs/design/30-workspace-graph.md#d314-发现是开放的依赖是授权的授权在切版本时判一次性)），
而切版本是 B5b。B5a 交付的是**授权的登记与查询**，以及**投影时的检查**：菜谱引用一张
没有被授权给本 workspace 的 graph → 结构化拒绝，消息要说「你没有权限引用它，去找谁」,
而不是「投影失败」。

**生效上限 = min(授权档位, `:up-to`)** 也在这一片算出来，随投影结果带走。

### ④ 越界写标记是**检测**，不是拒绝

[D3.4](../../../docs/design/30-workspace-graph.md#d34-写入不设防自律-镜子检测代替预防)：
写入时不校验 namespace 归属，**越界写不拒绝、只留痕**。

诱惑在于「顺手拒了不就干净了」。不行——D3.4 的论证是「越界写**利人损己**」（写进别人地盘
的对象，只有 own 那个 namespace 的 workspace 能装进 graph，写的人自己用不了），纪律靠激励
自我执行。改成拒绝会把 D3.3 写死的三档升级路径（`:warn` → `:block-new` → `:block-all`）
的第一档直接跳过，而那条路径是**现在就写死、免得届时变成政治讨论**的。

### ⑤ 债：投机校验——**先做差集，再谈范围**

[pool README 裁定 ②](../pool/README.md) 记着：B4.1 的投机校验把**整池**拼回方言交 B0 判,
前提是「B4 没有 workspace，整池 = 一个 namespace 宇宙」。这一片让那个前提失效。

**但「改成按投影范围拼」只解决了成本，没解决真正的病。** 病是这个：

> 池里任何一处不干净，**所有人的写都被拒**，而报出来的是「你的模型不合法」。

缩小范围只是把「所有人」换成「一片人」。真正的修法是**差集**：

1. 写之前对同一范围跑一次 B0，记下已有的 error；
2. 投机事务之后再跑一次；
3. **只有这次写引入的新 error 才拒绝**。已经存在的脏当 `:warning` 随行报出——
   它是真的，但**不是这次写的责任**，也不该由这次写来偿还。

**为什么差集是承重的那一半**：范围再小也可能已经脏（导入带进来的、规则改判之后的存量）。
只缩范围，那一片人照样被一个不是他们造成的问题挡住，而且**更难查**——因为报出来的位置
指向别人的对象。差集让拒绝永远指向**这次动作**，这正是 B4.1 把五步检查排在 B0 之前的
同一条理由（「前四步的拒绝能说出你这次动作错在哪，而 B0 只会说这份模型不合法」）。

**范围缩小是成本优化，排在差集之后**：作用域取「被写对象所属地盘 + 它引用到的地盘的
传递闭包」。只取本地盘会误报——地盘 A 的 resolver 引用地盘 B 的属性在池层面完全合法
（[D3.4](../../../docs/design/30-workspace-graph.md#d34-写入不设防自律-镜子检测代替预防)
是检测不是预防），只拼 A 会让 B0 说「属性未登记」。

**另一笔债不在这一片**：搜索索引键控要换成 graph 闭包 revision，而闭包 revision 要等
切版本（B5b），记在原处。

（原本还记着第二笔：「`scope.edn` 的修正层迁进池」。它 2026-08-24 **销账**了——
转换器与语料一并退休，`scope.edn` 不复存在，模型自己就是事实源，没有修正层可迁。
见 [fixtures/demo](../../../fixtures/demo/README.md)。）

## 裁定 ⑥：发现面报表进 B5a.3，且**只建现在建得了的那一半**

[D3.1](../../../docs/design/30-workspace-graph.md#d31-跨域组合是常态-共享池-投影) 说池只做
三件不出现在用户面前的事，其中**发现面是它不可替代的那一件**——把发现缩到「别人已 share
的 graph」，一个还没切过图的 domain 就完全不可见，[D3.14](../../../docs/design/30-workspace-graph.md#d314-发现是开放的依赖是授权的授权在切版本时判一次性)
的「找谁 request」退化成按登记表盲猜。

**但 [§3.3](../../../docs/design/30-workspace-graph.md#33-照镜子可见性义务) 那张清单有一半
现在建不了**，因为它们问的是**版本**与**部署**的问题：

| 报表 | 依赖 | 何时 |
|---|---|---|
| 归属（属性/namespace 归谁） | 地盘表 | **B5a.1 已有** |
| **引用反查**（谁引用 `core@v3`） | 菜谱 | **B5a.3** |
| **含量清单**（这个对象进了哪些图） | **投影** | **B5a.3**——它是投影的直接推论 |
| 越界写 / 无人认领 | B5a.1 的两册标记 | **B5a.3**（只差报表视图） |
| 滞后报告（server 上哪些版本还带旧状态） | server 控制面 | B5c |
| 僵尸版本 | 切版本 | B5b |

**含量清单跟着投影走，不单独做**：「这个属性进了哪些图」就是「对每张图跑一次投影、看它
在不在结果里」。分开实现等于把同一份闭包规则写两遍，而两份闭包规则迟早对不上——那时
报表会说「它在 A 图里」而 A 图实际投不出它。

**版本版与池内版是两回事，别混。** §3.3 的含量清单问的是「出现在哪些 **graph 版本**里」;
B5a.3 交付的是池内版——「**按当前菜谱**会进哪些图」。前者要等 B5b，两者**同时存在时必须
分开命名**，因为它们的答案会不一样（菜谱改了、还没重切）。
