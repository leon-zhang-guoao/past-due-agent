# 通用选择与展开：设计记录

原 Stage 3 设计记录。用户随后明确要求“参考现有的 edn 文件继续”，已授权按现有结构实现。
本地实现进展见 [3.5说明](../COMPOSABLE_ANALYSIS_3_5.md)；本文件中的平台能力设想不表示已实现。
依据与限制见 findings.md；业务问题映射见 coverage.md。

## 1. 职责

Agent 理解问题、维护一份分析规格、处理实质歧义、解释结果。
图负责校验、分母、选择、排名、展开、汇总与可计算的覆盖核对。
与数据绑定的限制进入关联知识；报告版式和通用操作步骤留在 Skill。

```text
用户问题 → 分析规格 → 图内校验与规范化
                       ↓
               基础事实与独立分母
                       ↓
                候选对象与排名选择
                       ↓
                 按选中身份展开
                       ↓
            指标／汇总／覆盖 → 传输分页
                       ↓
                 Agent 解释与交付
```

只扩展通用受控操作，不开放任意查询语言、任意表达式或源 SQL。
不额外创建只有单一用途的转发模块；保留现有日常报告与明细路径。

## 2. 一份规格，选择与展示分开

以下是概念数据结构，不是平台 schema，不承诺可直接作为 EDN 参数：

```text
scope:
  country, time, calendar, candidate_vendors, organization_filters
selection:
  unit: VENDOR | GROUPED_ROW
  partition: GLOBAL | TARGET_DATE
  metric, direction, change_selection, limit
  eta_filters
expansion:
  grain, eta_filters
denominator:
  COUNTRY_ALL | FILTERED_POPULATION | WITHIN_VENDOR
output:
  requested_measures, coverage
```

- scope 的候选集合在选择前固定；“全部”“显式集合”“内部无匹配”有不同身份。
- selection.metric 沿用已定义指标，不添加字符串表达式或自定义公式。
- Vendor 排名不使用展开后的桶值；GROUPED_ROW 保留现有按聚合行排名的能力。
- GLOBAL 与 TARGET_DATE 分开声明。后者每个实际目标日期分别取 N，日期不可脱离身份。
- selection.eta_filters 决定用哪些桶的指标选择对象；expansion.eta_filters 决定展示哪些桶。
  复合问法有实质歧义时由 Agent 澄清，图不猜“全部 ETA”是否继承选择条件。
- limit=0 的旧“全部”语义仍保留；内部选中集合为空时输出明确空路径，绝不转为 ALL。
- 组织分区、每个 Owner 排名等不在第一轮新增范围中；只有真实需求、维度与权限都明确才扩展。

## 3. 输入简化的实际落点

优先通过平台已支持的类型、默认值和保存查询封装确定性转换。
CURRENT 不应要求模型手填无意义的历史日期；SNAPSHOT、PAIR、RANGE 各自校验适用日期。
默认值必须可解释、可回显；不能用默认日期覆盖用户指定的日期。

目前尚未读取 get_contract_guide，因此不承诺原生可选输入或固定“两个参数”接口。
如果平台仅支持现有标量输入，评估固定时间类型的入口与版本化受控规格编码两种方案：

| 方案 | 收益 | 成本与采用条件 |
|---|---|---|
| 少量时间类型入口，共享内部实现 | 参数类型直接、少填无关日期 | 存在多个入口；需证实能复用且不使发现歧义增加 |
| 一个版本化受控规格编码 | 一份完整规格，能回显规范化结果 | JSON 只减少线上的字段数；校验复杂度仍存在，须严格拒绝未知字段和错误类型 |

读过契约、做过最小平台校验后再二选一。不并行建设两套入口，不改旧 22 参数的解释。

## 4. 图内执行与分母

执行顺序：时间／输入合法性 → 授权后的基础事实 → 原始总体／组织候选总体／Vendor 分母
→ 选择指标 → 带确定性顺序的排名 → 显式选中键 → 展开 → 测量与核对 → 分页。

选择键至少包含 Country、目标日期、Vendor；PAIR 还绑定实际 P/T 与完整范围。
展开按完整键连接，不跨日期混合入选 Vendor。组织映射先去重，不能放大业务事实。

COUNTRY_ALL、FILTERED_POPULATION、WITHIN_VENDOR 保持指标 3.1.0 含义。
Top N 作用于选择，不作用于分母。新模块复用选择前计算的分母，不能将选中 Vendor
重新作为 FILTERED_POPULATION 再计算，否则与原范围含义不同。
ETA 过滤后的分子与全 Vendor 比率分母也不混淆；零分母继续返回不可计算而不是零比例。

## 5. 输出与空路径

首轮建议增加可明确区分的选择、测量、覆盖和控制信息；具体是一组带类型的行还是
多个集合，服从平台契约，并以一次实际执行是否保持关联为准。

- CONTROL：规范化范围、指标版本、有效性、实际数据日期、总记录数量。
- 选择信息：实际入选日期×Vendor、选择指标、分区内排名、确定性并列顺序。
- 测量：对应完整键的指标与 ETA 展开；仅该类型的字段才是观测值。
- 覆盖：显式请求对象无源数据、组织排除、选择桶无匹配、排名排除、展开桶无匹配分开。
- EMPTY_SELECTION 是合法空结果，不伪造 FACT 零值，也不回退查询全部 Vendor。
- 请求“全部”时不强行枚举未见过的 Vendor 身份；实际无源行无法证明 Vendor 不存在。

Q15 这类“按 NR 排名后展开全部”必须同时返回选择指标和展开测量的各自范围，
不能让一列相同名称的计数在两种范围之间悄悄换义。

## 6. 一致性与分页

把排名与展开放进一次查询可减少模型搬运和独立调用间漂移，不证明源查询事务一致。
ClickHouse 的 CTE、不同源读取、变化中的明细均不能未经验证称为原子快照。

依次核实平台已有能力：

1. 若可完整保留一次结果并分页读取，核实源截断、保留上限、TTL 与权限；仅“有 handle”不够。
2. 若有可信且可固定的数据修订号，记录其覆盖哪些表和查询，分页绑定该版本。
3. 若两者都没有，保留现有指纹、数量、范围、唯一 ordinal 检查，并明确是漂移检测。

不为实现一致性默默新增表、缓存服务或 ETL；没有对应保证时诚实标注。
源分页继续可能重算整个聚合；性能优化要基于真实计划和指标，缩小预览不等于降低源成本。

## 7. 知识放置

| 内容 | 权威位置与迁移条件 |
|---|---|
| PD/Open、贡献、分母、选择与规范化 | 图中可执行计算；平台有声明式 metric 能力再按 guide 映射，不编造 EDN 键 |
| CURRENT 与历史差异、当前组织映射、数据无修订号、因果限制 | 数据关联知识，待 Builder 支持与实际 related_knowledge 验收 |
| 报告模块、语言、追问、有限恢复和交付步骤 | Agent Skill |
| 字段语义、身份与状态 | 图属性／实体描述，并由同一契约生成必要参考 |

知识迁移完成前保留现有必要限制，不能先删 Skill 后假定文章会到达。
每篇文章一个数据事实、窄关联；不复制验收题或把执行步骤放进文章。

## 8. 内部实现

构建器将 SQL 组织为明确内部阶段，最终统一组装。分页挂在显式输出阶段，
替代 build_explore_v2.py 对 SQL 尾部文本的 rsplit。
抽取仅针对实际共享的指标和输出逻辑，不新建通用编译框架或公开任意操作树。
新路径复用指标计算，旧 resolver 和 SQL 在首轮保持原样，以降低兼容风险。

## 9. 验收与兼容

对新的对外查询路径测试：

- 全局／逐日排名、Vendor／聚合行选择、稳定并列顺序；同 Vendor 只在入选日期展开。
- 所有时间类型和现有指标，三种分母与排名前总体，选择／展开筛选组合。
- 空候选、空选择、全部选择、零分母、零测量、无数据、组织与桶排除。
- 超过源和结果读取上限、页重复与缺失、数据变化、过期和错误 handle。
- 全部旧 resolver／绑定保持、标准报告、当前 PO／Owner、HTML 原行为。

旧指标的等价路径比较用于兼容，独立算例／源核对用于正确性，二者分别记录。
新路径通过后才修改 Prompt／Skill 路由；需要旧路径等价回退时不得改变分母和范围。
真实角色和真实 Agent 测试不能用合成 SQL 测试替代。尚未执行的项目保持 NOT_RUN。

## 10. 推荐实施顺序

1. 业务负责人评审 coverage 与 open-items；确认新选择语义和已知不可回答范围。
2. 获取 Builder 契约及现有图／源权限证据，决定输入与输出的真实支持形态。
3. 保存当前基线；小步新增图内选择与展开，分步校验，暂不发布。
4. 在查询接口处验证语义、空集合、兼容与性能，再精简 Skill 的搬运指令。
5. 验证文章关联、权限和真实问答；经负责人审阅后发布，独立新 Agent 重复验收。
