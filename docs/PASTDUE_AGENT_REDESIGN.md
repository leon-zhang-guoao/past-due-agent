# PastDue Agent v3.1 整体改造设计

## v3.1 已批准实施基线

本节和当前 `docs/API_V3.md`、Skill 契约是3.1权威设计；下方1.0记录保留作历史背景，不覆盖新接口与报告取数策略。

- 交付仍为 Prompt + 完整 Skill + Atlas EDN；无线上 Python、任意 SQL、新表或邮件发送。
- 时区为 America/Los_Angeles，按夏令时显示 PST/PDT 和实际偏移；完整快照早于本地今天。
- 统一分析规格（模式、语言、范围、时间、指标、粒度、筛选、分母、排名、模块）。日报只是预设。
- explore-query/rows 支持当前、快照、任意有效两期、区间；受控组合粒度、指标、筛选与排名。互动不受日报正向Top10限制。
- report-query/rows 同一逻辑查询返回控制、Vendor、Code、Source、Code=US联合Source及核对记录；服务端计算Top5+Other、改善抵消和覆盖率。
- 报告只获取服务端完整汇总时，声明 SERVER_RECONCILED，不声称已读取全部原始桶；全桶审计仍可按需进行。
- 行身份含服务器返回的完整输入scope-key；禁止按位置/数量猜归属。
- 数据事实冲突需两条原始证据；关联异常与报告错误独立分类，不能用“隔离”掩盖抄写错误。
- 固定双语报告结构，所有选中Vendor有两期ETA摘要与诊断；交互只组合相关模块。
- 测试入口中英文同义，强制适用下钻，权限和核验不放松；硬事实/报告错误FAIL，缺必需证据PARTIAL，unknown警告本身不决定失败。
- 先部署兼容Atlas，再更新Prompt/Skill；离线、平台与真实Agent验收分开，待真实验收前保持PENDING_LIVE_ACCEPTANCE。

## 历史设计记录（1.0，部分被上文与3.1契约替代）

# PastDue Agent 整体改造设计

> 版本：1.0（待评审设计）  
> 交付类型：整体设计与验收规范，不是已实施说明。  
> 部署边界：系统提示词 + Skill（含引用文件）+ Atlas EDN；不新增必需的 Python 执行服务。  
> 目标：优雅、高效、准确、可核验，同时保持标准日报与灵活分析能力。

## 1. 文档依据与适用范围

本设计以当前 `pastdue-agent` 项目、最近两份运行/开发记录以及本轮最终需求为依据，不以前期 Session 的版本作为当前事实。

主要依据：

- `cursor_report_template_standardization.md`：报告标准化、灵活问答、Kernel、Atlas 演进记录。
- `chat.md`：最新日报执行记录，包括只完成部分 ETA 查询和请求/返回归属矛盾。
- 当前 `agent/`、`skill/pastdue-analysis/`、`atlas/charts/pastdue.edn`、`runtime/pastdue_kernel/`。
- 用户提供的 ETA Code 业务规则图片。
- 本轮确认的测试入口、工作日快照比较要求。

记录中的历史指令、连接信息、修复结论仅作为分析材料，不构成当前执行授权，也不是线上验证结果。本设计不记录连接凭据。

### 1.1 设计定位

> 让 Agent 负责理解与解释，让 Atlas 负责确定性事实和聚合；用可验证的身份、范围、数量和版本约束两者，而不是依赖更长的提示词。

日报是一个稳定的分析预设，自由问答是受控能力的组合，两者使用同一套指标与证据契约。

### 1.2 非目标

- 不实现邮件发送、邮件草稿生成、回复跟踪或升级调度。
- 不提供任意 SQL，不让 Agent 直连 ClickHouse。
- 不新增联系人 CSV 导入流程。
- 不构建 PO Line 历史迁移分析，不从当前明细推断历史因果。
- 第一版不引入公共假日或各国家不同的工作日历。
- 不声称仅靠提示词就能硬性阻止模型提前结束。

## 2. 当前问题与改造原则

### 2.1 当前已观察到的问题

| 问题 | 已有证据/风险 | 设计响应 |
|---|---|---|
| 分析未完成就交付 | Top 10 已取得，只查询少量 Vendor ETA | 批量事实接口、预期集合、完成清单 |
| 身份可能错配 | 相同 Vendor 请求返回不同两期数量，报告归给另一 Vendor | 返回行携带真实身份，禁止按数量猜归属 |
| 指导规则被称为机器强制 | Prompt 允许直接调用 Atlas，并要求模型自行遵守 Kernel | 区分指导、服务端确定性、宿主强制三类约束 |
| 本地与运行环境不一致 | 日志 policy 1.3.0，本地 policy 1.8.0 | 发布清单、兼容检查、线上版本取证 |
| 本地 Kernel 尚非真实运行闭环 | 查询形状与当前 MCP 不一致；存在 marker 和待展开项 | 不作为生产必需执行器，不宣传已接管 |
| 指标被技术修复改变 | 当前排名的 Vendor 内比例恒为 1 | 冻结指标公式，语义变更版本化 |
| 灵活问答过于场景化 | 新问法不断增加意图和专用路径 | 分析规格 + 按粒度建模的可组合能力 |
| 查询成功与完整混淆 | `source-completeness: unknown` | 单独证明任务、集合和数量完整性 |
| 模板与分析口径漂移 | 同问可能按 Vendor 或整体聚合 | 规格中固定分母与展示粒度 |

最新日志中的请求/返回矛盾必须先用原始 MCP 请求和服务端执行记录核实。不能仅凭日志确认是缓存、模型、导出或 Atlas 的哪一层故障。

### 2.2 设计原则

1. **单一语义来源**：公式、时间、范围和分母不能在多个文件中分别定义。
2. **先确定问题，再选择能力与模板**：不由现有模板反推用户问题。
3. **固定流程可复用，探索问题可组合**：不为每句话新增业务场景。
4. **机械工作下沉**：减少模型逐 Vendor 调度、参数复制和大规模心算。
5. **失败最小化隔离**：一个维度失败不抹掉其他已核实事实。
6. **证据优先于解释**：身份不明或数据不全时，不生成确定性业务判断。
7. **效率优化不得改变口径**：缩小分母、只扫逾期行等操作必须保持指标定义。
8. **不夸大保证**：明确哪些机制已经执行、哪些仅为模型指导。

## 4. 总体架构与职责

```text
用户 / 外部每日调度
        │
        ▼
分析规格：模式、时间、范围、指标、粒度、分母、展示
        │
        ▼
能力规划：日报预设 / 历史预设 / 受控分析组合
        │
        ▼
Open Atlas MCP
  ├─ 工作日快照与 Country 指标
  ├─ 固定日期对 Vendor 比较与 Top N
  ├─ 批量 ETA Code / Source / 必要联合分布
  ├─ 当前聚合与明细
  └─ 组织、Owner、联系人
        │
        ▼
核对：身份 + 选中集合 + 集合完整性 + 数量 + 版本
        │
        ▼

        │
        ▼

```

这是职责分层，不要求增加多个 Agent、服务或中间件。

| 交付物 | 负责 | 不负责 |
|---|---|---|
| System Prompt | 角色、可信原则、时间边界、模式入口 | 大量 EQL 细节、复制指标公式 |
| Skill | 规格解析、流程组合、异常处理、规则应用 | 假装执行了未接入的 Runtime |
| Policy / 指标契约 | 唯一阈值、日历、选择规则、公式 | 多版本散落定义 |
| 展示契约 | 模块字段、顺序、格式、组合 | 改变分析口径 |
| 诊断规则契约 | Code 含义、条件、证据要求、核查建议 | 直接证明业务根因 |
| Atlas EDN | 参数、SQL、绑定、事实身份、聚合、核对字段 | 自行理解用户意图 |
| 测试和发布资料 | 兼容性、部署清单、真实验收证据 | 用模拟 PASS 代替线上可用 |

## 5. 统一分析规格与模式

### 5.1 分析规格

以下是概念性结构，不是可直接部署的 Atlas schema：

```text
mode: DAILY | HISTORICAL | INTERACTIVE | TEST
time_basis: CURRENT | SNAPSHOT | SNAPSHOT_PAIR | RANGE
calendar: WEEKDAYS | CALENDAR_DAYS
countries: [US, CA]
target_date / previous_date / range
metrics: 已声明指标
dimensions: 已声明维度
filters: 已授权筛选条件
ranking: 指标、方向、稳定次序、Top N
denominator_scope: COUNTRY_ALL | FILTERED_POPULATION | WITHIN_VENDOR
display_grain: PER_VENDOR | COMBINED
requested_modules: 默认模块 + 明确要求的可选模块
```

### 5.2 默认语义

- “开始日报 / start daily monitor”：DAILY，工作日快照，US/CA。
- “开始测试”：TEST，工作日快照，US/CA，强制下钻。
- “过去一周哪些天触发”：HISTORICAL，范围 D−7 至 D−1，默认工作日口径；不是最近 7 个工作日。
- “现在 / 实时 / 当前排名”：CURRENT，标注为当前可读状态，不承诺秒级实时。
- 脱离日报上下文的“逾期最多 Top N”：按逾期数量，不默认解释为增长贡献。
- 日报内的 Vendor Top 10：正向 Country 贡献变化排名。
- “这些 Vendor 的 ETA 占比”：默认逐 Vendor 内部构成；只有“合并/整体/合计”才合并。
- “Vendor detail”：当前明细模块，默认逾期明细并说明筛选，不自动等同于“仅高风险”；未指定 Country 且无法从上下文确定时先澄清。

默认值必须在报告口径中简要呈现。对时间、分母或范围存在实质歧义且无可靠上下文时，才询问用户；不反复询问确定性的日期换算。

### 5.3 模式行为

| 模式 | 下钻条件 | 日期 | 展示 |
|---|---|---|---|
| DAILY | 达阈值/零基线上升且数据符合分析条件 | 最新两期完整工作日 | Country + 触发国 Vendor 摘要 + 业务总结 |
| HISTORICAL | 默认每国最新触发事件；只列事件时不下钻 | 指定范围与合法日期对 | 事件表 + 选中事件的同一套分析模块 |
| INTERACTIVE | 按问题所需 | 当前态或明确快照 | 仅相关模块 |
| TEST | 跳过阈值门槛，尝试完整必需流程 | 默认同 DAILY | `[TEST]` 标记 + 标准模块 + 测试检查表 |

历史显式全部事件下钻仍保留每 Country 最多 5 个事件、最大范围 366 日的限制，超出时说明边界。

## 6. 工作日、完整快照与新鲜度

### 6.1 第一版工作日

- 统一 PST。
- 工作日为周一至周五。
- 周六、周日快照不进入默认日报比较。
- 暂不排除公共假日，不按 US/CA 分别推断当地假期。
- `snapshot_date < current_pst_date` 是必要完整性条件；本规则并不能证明上游所有分区已经到齐。
- 如果以后存在 ETL 完成标记，应作为额外就绪条件接入；第一版如无该标记，明确此限制。

### 6.2 日期选择

对每个 Country：

```text
D = 当前 PST 日期
eligible_dates = 实际存在、日期 < D、且为周一至周五的快照日期
T = max(eligible_dates)
P = max(date ∈ eligible_dates 且 date < T)
```

历史工作日口径下，目标日期必须为工作日，P 是目标日前最近可用的完整工作日快照。若用户显式要求日历日回溯，目标和 P 均切换为日历日规则。

**必须同步修改 Atlas 的日期选择和日期对合法性检查。** 原来只接受“上一日历快照”的接口，不能原样用来拒绝“周一→周五”的工作日对。

### 6.3 快照日期不是运行日期

| 运行 PST 日期 | 正常本期 T | 正常上期 P |
|---|---|---|
| 周一 | 上周五 | 上周四 |
| 周二 | 周一 | 上周五 |
| 周六/周日 | 周五 | 周四 |

“周一与上周五比较”是指周一快照，不表示周一运行时可以读取当天未完成快照。

示例：2026-10-27（周二）运行时，可比较 2026-10-26（周一）与 2026-10-23（周五）。

### 6.4 缺失与过期

定义：

- `expected_target_date`：D 之前最近的周一至周五日期。
- `target_lag_workdays`：从 T 之后至 expected_target_date（包含）应有但尚未追上的工作日数。
- `missing_workdays_between`：P 与 T 之间本应有快照但缺失的工作日数，不计正常周末。
- `calendar_gap_days`：T−P 的日历天数。

建议迁移配置：保留原“超过 2 天过期”的阈值数值，但单位明确改为 **工作日**，即 `target_lag_workdays > 2` 标记 STALE；滞后 1–2 个工作日仍须告警示数据延迟。此项作为本设计默认值，可配置，禁止隐式换单位。

实际日期可回退到最近可用工作日，但必须显示缺失。生产日报遇到 STALE/不可比较时，输出指标与限制，不自动宣称执行了有效的最新告警下钻；TEST 可继续分析合法但过期的日期对，并标记过期。

跨周末写“较上一可用工作日快照，间隔 3 个日历日”，不能写“较昨天”。增长阈值不按间隔天数折算。

### 6.5 周末运行和重复事件

周末也输出摘要，注明最近工作日日期对及“无新增工作日快照”。同一事件键为：

```text
Country + T + P + 指标/规则版本 + 日历口径
```

事实相同的日期对不是新事件。没有跨运行持久化状态时，只能确定性识别同一个日期对，不能保证“是否此前已通知”的全局去重。本项目不发送通知，不新增隐藏状态服务。

## 7. 指标语义与选择规则

### 7.1 Country

```text
R_T = past_due_T / open_T
R_P = past_due_P / open_P
relative_change = (R_T - R_P) / R_P
point_change_pp = (R_T - R_P) × 100
```

- R_P > 0：relative_change ≥ 0.10 触发。
- R_P = 0 且 R_T > 0：ZERO_BASELINE_INCREASE，进入下钻。
- 两期 Ratio 均为零：NORMAL。
- Open=0 且逾期=0：Ratio 展示为不适用/无 Open，不等同于“Open>0、逾期=0”的正常零基线；两期比较不足以得出常规相对增长。
- Open=0 且逾期>0，或逾期超过 Open：数据异常。
- 分类使用原始精度，展示才四舍五入。

### 7.2 Vendor

```text
C_T(v) = past_due_T(v) / country_open_T
C_P(v) = past_due_P(v) / country_open_P
delta_C(v) = C_T(v) - C_P(v)
positive_share(v) = delta_C(v) / Σ max(delta_C(all vendors), 0)
```

- 只选 delta_C>0。
- delta_C 降序、Vendor Code 升序，取前 10。
- 不足 10 家返回实际数量；零家不补入负贡献 Vendor。
- 80% 仅为参考，不提前停止。
- Top 10 覆盖率 = 所选正向贡献 / 全部正向贡献，不是 Country 净上升解释比例。
- 校验全量 Vendor delta 之和与 Country Ratio 变化一致；Top 10 不承担全量净变化核对。

### 7.3 其他易混指标

| 指标 | 分子 | 分母 |
|---|---|---|
| Vendor 自身逾期率 | Vendor 逾期行数 | 同口径 Vendor Open |
| Vendor Country 逾期份额 | Vendor 逾期行数 | Country 逾期行数 |
| Vendor 内 ETA 占比 | 某 ETA 逾期行数 | Vendor 逾期行数 |
| 筛选群体内 Vendor 占比 | Vendor 逾期行数 | 筛选群体逾期行数 |

当前明细与快照 Open 是否口径一致，需要核实物理数据定义；不能仅按表名假定一致。若只查询逾期行，就不能暴露“Vendor 全量 Open”或恒为 100% 的“Vendor 逾期率”。旧字段不能静默改义，应新建明确字段/版本，并给出弃用说明。

### 7.4 组织过滤

- 组织真值来自 `vendor_master_mapping_view`，键包含 Country + Vendor。
- 不使用 detail 中的 `department_type/master_primary/master_manager` 作为组织真值。
- Buyer 邮箱来自当前明细/Owner 事实，ETAD Primary 用于 ETA Specialist。
- 多条 Mapping 使用去重集合、半连接或预聚合，不能放大 PO 数量。
- 无组织过滤时，默认全 Country，不因缺少 Mapping 自动排除 Vendor。
- 如需“仅有映射 Vendor”，作为显式分析范围，相关分母也明确标记。
- 组织筛选作用范围与分母作用范围分开：查某 Manager 的 Vendor 在全 Country 的份额，分母不能随组织过滤缩小。

## 8. ETA 两期事实、排序与核对

### 8.1 全量事实

Code 与 Source 均返回两期出现过的所有项，包括负变化、零变化和 `UNKNOWN`。先确认两期与查询完整，再将某一期缺失桶计零；查询失败绝不是零。

```text
count_delta = target_count - previous_count
relative_count_change = count_delta / previous_count  （previous_count>0）
```

- 上期为零、本期为正：相对变化 null，展示“零基线上升”。
- 两期均零：相对变化 null，展示“无变化”。
- 从正数降为零：−100%。

### 8.2 展示

按以下稳定顺序选 Top 5：

1. abs(count_delta) 降序；
2. target_count 降序；
3. ETA 值升序。

剩余项合并“其他（N 项）”。两期分别求和后再算变化率，不能平均百分比。另计算增加合计、减少合计（负数）与净变化。

默认日报展示摘要列表，完整表按需展开。摘要可不逐项列零变化，但必须保留全量事实用于核对，不能以“无显著变化”代替未查询。

### 8.3 独立核对

- Code 上期/本期合计分别等于 Vendor 上期/本期逾期数量。
- Source 独立执行同样核对。
- 数量采用整数精确相等。
- 贡献优先从完整数量和共同分母计算，避免累加已截断显示值。
- 比例核对默认 abs/rel tolerance 1e−9；若 Atlas 必须返回定标 Decimal，容差需按实际量化精度和桶数明确定义，不能为了过测放宽。
- Code 与 Source 是对同一数据的两种划分，不能相加。

## 9. Atlas 能力设计

### 9.1 能力族

| 能力族 | 支持的问题 | 关键约束 |
|---|---|---|
| 快照指标 | Country/Vendor 指标、日期选择 | 工作日口径、日期固定 |
| 两期比较 | Vendor 变化、贡献排名、全量抵消 | 同一日期对、全量分母 |
| ETA 比较与构成 | Code/Source 全量变化、占比 | 批量、真实身份、完整桶 |
| 当前聚合 | Vendor 排名、ETA/Alert 分布 | 指标/粒度白名单 |
| 当前明细 | PO 条件筛选 | 稳定排序、分页、权限 |
| 组织/联系人 | Specialist、Owner、收件人 | 当前上下文、敏感字段治理 |

按分析粒度建立接口，不为每个中文问句建立 resolver。

### 9.2 拟新增/调整接口

以下名称是设计建议，最终以 Atlas schema 兼容验证与发现结果为准，不能直接将本表当可调用工具。

| 逻辑入口 | 输入 | 返回 |
|---|---|---|
| Country 工作日监控 | Country / 日历 | T/P、指标、预期日期、缺失/滞后 |
| 日期对 Vendor 比较 | Country、T、P、日历 | 全量或受控 Top N、选择依据、覆盖率 |
| 日期对批量 Code 变化 | 同一选择范围、Country、T、P | 各选中 Vendor 的所有 Code 两期事实 |
| 日期对批量 Source 变化 | 同上 | 各选中 Vendor 的所有 Source 两期事实 |
| US 联合分布变化 | 同上，Code=US | Vendor × Code × Source 两期事实 |
| 当前态受控聚合 | Country、粒度、指标、合法过滤 | 聚合事实与分母范围 |
| 查询核对信息 | 同一次分析范围 | 选中集合、预期/实际数量、总量、限制 |

原有单 Vendor changes 和显式 positive drivers 保留兼容；drivers 不能作为全量变化或占比的替代。

### 9.3 批量设计：减少模型循环，不制造巨型接口

默认每个触发 Country 使用：

```text
固定日期对和选择规则
  → Vendor Top 10 与选中集合
  → 批量 Code
  → 批量 Source
  → 必要时批量 US 联合事实
  → 核对
```

首选在 Atlas SQL 中复用相同日期对和 Vendor 选择 CTE，避免必需新增列表参数能力。若平台确认支持安全的 Vendor 集合参数，可以传入显式集合；不能拼接字符串构造 `IN (...)`。

每个批次独立返回一类事实。不得将 Code 与 Source 直接交叉连接，避免行数乘法。若单批超限，按可验证的 Vendor 分片处理，不能对全批简单加 `LIMIT 100` 后宣称已覆盖十家。

Top N 在 Vendor 层选取；ETA 桶分页不等于 Vendor 选择，也不等于展示 Top 5。

### 9.4 结果身份与证据契约

每条 ETA 事实至少带：

```text
country_code
vendor_code
target_snapshot_date
previous_snapshot_date
eta_code / eta_source
previous_past_due_count
target_past_due_count
past_due_count_change
```

另需通过合法属性或核对集合提供：

- metric/calendar/selection 版本；
- 选中 Vendor 集合及稳定排名；
- 每 Vendor、每维度的实际桶数及两期合计；
- 分页结束、内部限制等可证明信息；
- 图版本、查询时间和结果 handle（平台提供时）；
- 上游数据水位/修订版本（存在时）。

行身份必须来自实际分组和关联键，不能仅把请求中的 Vendor 原样贴回结果。请求摘要/集合摘要可辅助检测漂移，但不构成数据真实性的独立证明。

无数据的 Vendor 必须通过选中清单和核对结果区分“成功空结果”“遗漏”“查询失败”；不能仅依赖没有返回行。

### 9.5 一致性与缓存

- 同一任务固定 Country/T/P/日历/选择规则，不重新计算 latest。
- Code/Source 使用同一选中集合；发现漂移不能混合生成报告。
- 历史快照可能被回填修订；固定日期不等于事务一致。
- 若存在数据版本，各查询须对齐；无版本时执行数量与集合核对，并披露跨查询一致性的限制。
- 缓存键覆盖完整身份、过滤、分母范围、指标与图版本、权限上下文；当前态使用短 TTL/平台适当策略。
- 过期 handle、其他任务/环境 handle 不得用于本次分析。

### 9.6 受控灵活查询

支持白名单指标 + 白名单分组 + 合法过滤 + 排序/Top N。表名、列名、任意 SQL 不接受用户字符串插入。

Atlas 若不支持参数化分组，则提供少量粒度接口：Vendor、Vendor×Code、Vendor×Source、Vendor×Alert Type。不要假设仅改 EDN 就自动拥有通用查询编译器。

排名和分母在完整授权数据范围内计算，再做结果分页。不能使用第一页明细计算全国排名或“全部占比”。

## 10. ETA 业务诊断能力

### 10.1 规则表

| ETA Code | 用户提供的业务含义 | 默认诊断方向 | 建议核查 |
|---|---|---|---|
| DD | Warehouse 收货不及时 | 仓库收货/入库处理及时性 | 核查实际到货与收货登记进度 |
| SH | 未及时送达/收货 | 交付或收货延迟 | 核查运输送达及收货进度，不能只归咎其中一方 |
| SC | Vendor 预计发货时间不准确 | 发货时间承诺可靠性 | 核查承诺日期与更新情况 |
| US + AutoUS | Vendor 给的 ETA 已 past due | 已有 ETA 失效/需更新 | 核查原 ETA 有效性与下一次更新 |
| US + 其他已识别 Source | Vendor 只给了粗略时间 | 时间信息精度不足 | 核查更明确的交期 |
| NR | Vendor 已收到订单，但未提供预计发货时间 | ETA 信息缺失 | 核查预计发货时间补充进度 |
| RQ | 未收到 Vendor 确认信息 ACK | 订单确认反馈缺失 | 核查订单接收与 ACK 反馈 |

US+UNKNOWN 不能套“其他已识别 Source”规则。未知 Code 保留数据，标记“暂无规则”。Source 的 AutoUS 规范值与别名应通过发现和数据核实确认；可以 trim/大小写规范化，不做无依据模糊匹配。

### 10.2 联合证据

当选中 Vendor 任一期 US 逾期数量>0 时，获取 US 对应的 Source 联合分布。独立 Code/Source 两张表不能相互拼接解释。

```text
US Code +30，AutoUS Source +30
不等于 US×AutoUS +30
```

联合事实的两期数量应分别还原 US Code 两期数量。其结果只是进一步拆分，不再与 Code 总量相加。

### 10.3 诊断顺序

1. 读取核对通过的事实，识别数量增加与减少。
2. 应用 Code 规则，US 使用联合证据。
3. 同时检查 Vendor 数量和 Country 分母影响。
4. 描述改善抵消与净变化。
5. 给出建议核查方向，区分事实、规则解释、假设与行动。

数量减少但 Country 贡献上升时，优先解释分母收缩，不能写成“该业务问题加剧”。Code 代表风险信号，不证明部门/个人造成了变动。

### 10.4 Vendor 与 Country 总结

每个选中 Vendor 都输出业务摘要或明确不可用原因：主要增加项、改善项、业务含义、核查建议、限制。

每个触发 Country 总结：主要风险环节、集中 Vendor、改善抵消、优先核查、覆盖范围。默认仅基于选中 Top 10，不能写成“全 Country 的业务问题分布”。用户要求全 Country 时另做全量聚合。

诊断优先级可按相关桶的正向数量变化及贡献展示，不生成无依据的概率或“95% 置信度”。

## 11. 工作流与执行预算

### 11.1 正常日报

```text
核对发布兼容与可用能力
→ 获取所有监控 Country 工作日指标
→ 固定各 Country 的 T/P
→ 计算真实业务状态和数据状态
→ 仅对符合条件的触发 Country 取 Top 10
→ 批量 Code / Source / 必要联合事实
→ 完整性核对
→ 规则诊断
→ 标准报告与跨 Country 总结
```

非触发 Country 不查询 Vendor Top 10；避免最新日志中对 NORMAL Country 的无关消耗。

### 11.2 历史

范围默认按日历日期计算，但过滤为工作日目标；上期可早于范围起点。默认每国最新触发事件下钻。用户只要事件列表时不下钻。历史事件不冒充当前告警，当前 Owner/PO/联系人单独标记。

### 11.3 调度与预算

- 默认少量批量调用，不能把“20 次查询”优化成一个超大且不可校验的结果。
- 并发预算以 Atlas 实际限额为准，初始保守 1–2；本交付范围内它是 Skill 调用纪律，不伪称宿主硬限制。
- 发现结果可在同任务、同环境版本内复用；不每个 Vendor 重复发现，也不跨版本盲用缓存。
- 能力不兼容时先一次性修复可检测问题，不盲猜字段重试。
- 每个逻辑请求最多一次纠正/恢复重试；同一工作键重复发送不视为新工作。
- 批量失败可分片隔离，但重试/降级共享预算，禁止递归拆分形成请求风暴。
- 长报告优先使用紧凑摘要，不以省篇幅为理由少查事实。

## 12. “开始测试”功能

### 12.1 入口

```text
开始测试
开始测试，只测试 CA
开始测试，指定 2026-10-26
开始测试，包含联系人和 PO 明细
```

默认 US/CA，最新两期完整工作日快照。指定目标日期时按该日历规则解析比较日期；非法周末目标不静默换成其他日期，应说明并让用户选择显式日历日测试或合法工作日。

### 12.2 仅覆盖下钻门槛

- 不修改 10% 真实阈值。
- Country 仍输出真实 NORMAL/TRIGGERED 等判定。
- 无论阈值是否达到，均尝试 Top 10、Code、Source、必要联合、核对和业务总结。
- 标题 `[TEST]`，下钻原因为 TEST_FORCED；已真实触发者可标 THRESHOLD_MET。
- 报告说明测试强制下钻不构成新增真实告警。
- 不触发邮件、升级或通知动作；联系人要求仅展示。

### 12.3 完整测试的边界

“完整”指标准日报必需模块，不自动查询所有可选功能。无正向 Vendor 时给出成功空结果和“不适用”的 ETA 模块，不补负贡献 Vendor。

TEST 不绕过权限、合法日期、缺失快照或身份核对。过期但可比较的日期对可继续，保留过期警告；不足两期时不能完成两期测试。

### 12.4 测试结果

| 检查项 | 结果 |
|---|---|
| Country 日期与指标 | 通过/失败 |
| 预期 Vendor 集合 | 数量与身份 |
| Code/Source 覆盖 | 已核实数/预期数 |
| US 联合分析 | 通过/失败/不适用 |
| 身份、分页、数量、版本 | 通过/失败/未验证 |
| 业务诊断与必需报告模块 | 完成/部分完成 |
| 总体测试 | PASS/PARTIAL/FAIL |

全部适用必需检查通过才为 PASS；身份/数量错误等硬失败为 FAIL；外部失败或完整性未证实为 PARTIAL，不称完整通过。不适用应有理由。无正向 Vendor 的 PASS 仅表示适用流程通过，不能据此宣称十家 ETA 路径已获覆盖。

## 13. 可信状态、失败隔离与证据

### 13.1 分离状态轴

- `business_status`：NORMAL / TRIGGERED / ZERO_BASELINE_INCREASE / NOT_EVALUABLE。
- `data_status`：OK / DELAYED / STALE / INSUFFICIENT / ACCESS_DENIED / DATA_ERROR。
- `analysis_status`：COMPLETE / PARTIAL / UNAVAILABLE / NOT_REQUIRED。
- `drilldown_reason`：THRESHOLD_MET / TEST_FORCED / USER_REQUESTED / NONE。

例如 Country 可同时为 TRIGGERED + OK + PARTIAL，保留真实触发事实，不用下钻失败覆盖它。

### 13.2 结果核对闸门

1. **范围**：实际 Vendor 集合等于预期集合，Country 不串用。
2. **身份**：每行 Vendor、T/P、日历、选择规则一致。
3. **集合**：分页/内部限制可解释，不能只看返回行数少于 limit。
4. **数量**：Code/Source 独立还原 Vendor，两期和联合分别核对。
5. **版本**：无明显环境/指标/结果版本混用。

`result-complete=true`、`truncated=false` 只能说明相应返回/物化层情况，不自动证明底层集合完整；`coverage-unknown` 也不是一定缺数。必须结合范围证据和核对。

数值相等是必要检查，不是身份和全集完整性的替代证明。

### 13.3 错误处理

| 情况 | 行为 |
|---|---|
| 身份错配 | 隔离结果，一次核实/纠正，禁止按数量重新认领 |
| 日期/选择集合漂移 | 重新固定范围，不能混合报告 |
| Source 失败 | 保留已核实 Code，继续其他独立工作 |
| 批量 SQL 失败 | 该批失败，不伪造逐 Vendor 成功状态；按预算尝试小批隔离 |
| 拒绝访问 | 不重试绕过，不用其他入口获取同一被拒事实 |
| 未取完整 | 不算其他和全集合计，不声称全量诊断 |
| 结果为空 | 仅成功且范围清楚时解释为无数据 |
| 宿主中断 | 必须有宿主证据；不能由模型事后编造原因 |

完整性清单按 Vendor×维度记录“成功并核对、失败、未验证、未执行”。最后两类不算完成。系统性错误不能靠大量逐家重试隐藏。

## 14. 标准报告与展示契约

### 14.1 默认日报结构

1. 标题、运行 PST 时间、日历/日期口径、版本摘要。
2. Country 指标表，所有监控 Country 均有一行。
3. 每个需要下钻的 Country：
   - 触发/测试原因与比较日期；
   - Top 10 Vendor 汇总；
   - 按 Vendor 的业务诊断（可合并在摘要列）；
   - Country 业务总结、覆盖率和限制。
4. 跨 Country 总结，不混排 Vendor。
5. 分析完成检查；TEST 追加测试结果。

同一日期对可通过正常日报、测试、历史入口使用相同分析模块。

### 14.2 核心模块字段顺序

**Country 指标：**

```text
Country | 业务状态 | 数据状态 | 本期日期 | 上期日期 | 日历间隔
| 逾期行数 上期→本期 | Open 上期→本期 | 逾期率 上期→本期
| 相对变化 | 百分点变化 | 分析状态
```

**Vendor 摘要：**

```text
排名 | Vendor Code | Vendor 名称 | 逾期行数 上期→本期 | 净变化
| Country 贡献变化 pp | 正向贡献占比
| ETA Code 变化摘要 | ETA Source 变化摘要 | 业务诊断摘要 | 分析状态
```

覆盖率在 Country 段统一展示。累计占比保留在事实层；详细 Vendor 指标模块按需显示 Open、Vendor 逾期率、两期 Country 贡献，不为简洁而省略查询必要事实。

**完整 ETA 表：**

```text
ETA 值 | 上期逾期行数 | 本期逾期行数 | 净变化 | 相对变化
| Country 贡献变化 pp
```

Code 和 Source 使用相同字段；完整展开含 Top 5+其他、增加/减少/净变化、核对状态。

**US 联合解释：**

```text
Vendor | ETA Code | ETA Source | 上期数量 | 本期数量 | 净变化 | 规则解释
```

### 14.3 固定与通用模块

- 有专用模块时严格复用，不按问题重新发明表头。
- 新维度组合使用通用分析模块；列来自已声明指标和维度，仍固定名称、单位与格式。
- 不能因为缺模板就伪称数据能力缺失，也不应强迫所有新问题只能散文回答。
- 显示语言匹配请求；调度入口使用其指定语言。

### 14.4 格式

- 日期 `YYYY-MM-DD`，时间明确 PST。
- 比率/占比显示两位小数和 `%`。
- 百分点/贡献变化显示 `+1.50 pp`。
- 整数不加千位分隔符，带符号变化 `+12 / −5 / 0`。
- 上期→本期统一箭头。
- 真空值、失败、未查询、不适用分开；失败不能填 `0`。
- 所有计算使用原始值，显示四舍五入不得影响触发与排名。
- 事实层保留精度；小于显示精度但非零的关键值可按契约显示 `<0.01 pp` 等说明，不能误导为严格零。

## 15. 当前 Owner、联系人与 PO

这些模块保留能力但默认按需，不挤占默认 ETA 分析。

- Owner：Buyer → Primary → Manager，真实来源和当前查询时间明确。
- 联系人：Atlas 获取，Country + Vendor + Recipient Type 等必填条件按发现结果执行。
- 通知规则保持独立：SC/NR/US/RQ → Vendor，CC EMT+Buyer；SH/LS → Buyer；DD → Warehouse，CC Buyer。
- 未知 Code 或没有路由规则时显示未配置，不凭诊断词推导邮箱。
- 多个适用 Code 使用明确规则合并、去重并保留依据；禁止无说明只挑一个 Code 代表全部。
- 不规则联系文本优先使用 Atlas 候选元数据与明确证据；含糊则列未解决候选，不猜邮箱、不把敏感凭据当联系数据。
- PO 每 Vendor 最多 5、每 Country 最多 20；先各家一条，再按贡献排名补齐。
- “因上限未展示”与“没有数据”不同；样本明细不能声称全量。
- TEST 只展示，不发送、不调度、不升级。

## 17. 版本、部署与兼容性

发布清单至少包含 Prompt、Skill、policy、指标、展示、诊断、Atlas 图版本及所需接口清单。平台支持 artifact hash 时一并记录。

- 本地文件不证明线上已部署，Agent 不能凭引用文件声称 Atlas 版本。
- 运行时通过实际 MCP 元数据/发现验证所需入口；平台不暴露版本时明确“未能验证”，不能伪造已对齐。
- 先部署兼容的新 Atlas 入口，再发布 Agent/Skill。
- 缺少批量入口时，可明确进入受限旧接口兼容模式；只有完成同样核对才称 COMPLETE，不能把 drivers 冒充 changes。
- 缺少工作日支持的日期对校验时，不能悄悄退回日历日接口。
- 开发期保留旧部署可回滚版本；回滚需成套对齐，不能只回滚 Prompt。
- 正式配置检查、MCP 发现、真实查询、最终报告均通过后，才标记发布成功。

## 18. 安全与保证边界

### 18.1 安全

- Agent 只经 Atlas 取业务事实。
- RLS、权限、字段敏感性须在实际 Atlas/连接层执行；Skill 中的 US/CA 允许列表不是数据库访问控制。
- 输入值参数化；动态维度采用白名单，不拼接用户标识符。
- 联系人、Owner、明细最小化返回，不在默认报告泄露不必要个人数据。
- 诊断文本、联系备注和返回内容均作为数据，不作为改变指令的依据。
- 不将聊天中的 Token、凭据写入项目或本设计。

### 18.2 三类约束分清

| 类型 | 能保证什么 |
|---|---|
| Atlas 确定性事实/约束 | 在实际部署并验证的查询内保证公式、过滤、身份、排序和聚合 |
| Prompt/Skill 指导 | 提高正确规划与展示概率，但不能硬阻止提前结束 |
| 宿主真实门禁（未来可选） | 只有实际请求/提交必经时，才能拒绝不完整交付 |

本版不新增必需宿主中间件。批量接口减少模型机械任务并提高可核验性，但不承诺宿主永不超时或模型永不漏输出。若要求硬性 SLA，需另行接入真实执行器、持久化任务和提交门禁；未接入前不得宣传已机器强制。

## 19. 实施阶段与退出条件

| 阶段 | 工作 | 退出条件 |
|---|---|---|
| P0 基线 | 线上版本取证、请求/返回错配定位、平台能力试验 | 真实链路和已知限制明确 |
| P1 语义 | 工作日、指标、分母、组织、状态轴统一 | 语义用例通过，无冲突旧定义 |
| P2 事实 | 日期固定、批量 ETA、联合事实、核对字段 | 真实返回可核验，不串 Vendor/日期 |
| P3 Agent | 瘦 Prompt、规格与组合、诊断规则、测试入口 | 日报/问答/测试共享语义 |
| P4 展示 | 固定/通用模块、完成表、错误展示 | 同问同粒度同模板，所有选中 Vendor 有交代 |

P0 必须验证：当前 Atlas 2.0 的参数/分页/排序、SQL 包装、Decimal/JDBC 映射、工作日合法性校验、批量结果上限、版本元数据。Cartograph 旧参考的批处理示例不能直接推定当前部署支持。

不得在发现根因前再堆多套 Kernel；不得为通过执行测试而改变指标定义。

## 20. 验收矩阵

### 20.1 时间与业务触发

| 用例 | 预期 |
|---|---|
| 周二运行 | 周一 vs 上周五；所有层日期相同 |
| 周一运行 | 上周五 vs 上周四，不读取当天未完成快照 |
| 周末存在更晚快照 | 默认忽略周末快照 |
| 预期工作日快照缺失 | 回退并显示缺失、滞后，不能写“较昨天” |
| 正常周末跨度 | 不计为额外滞后工作日 |
| 历史范围起点 | 上期可在范围之前，日历规则一致 |
| 明确包含周末 | 日历日模式显著标注，不污染默认日报 |
| 9.999…% / 10% | 使用未四舍五入值，分别不触发/触发 |
| 零基线、Open=0 | 按指标规则区分，不输出 Infinity/NaN |

### 20.2 范围与完整性

- 前 3 家已覆盖 80%，仍分析所选前 10。
- 只有 6 家正向贡献，展示 6 家；零家明确不适用。
- US/CA 同时触发，各自独立完成，不混排名。
- 未触发 Country 不浪费默认 Vendor/ETA 调用。
- 批量结果跨页、不足 limit、内部截断、漏掉某家均能被检查识别。
- 相同 Vendor Code 跨国家不串数据。
- 同一请求返回疑似另一家数据时拒绝归属，即使数量“对得上”。
- Code 失败、Source 成功及其他 Vendor 可继续；所有失败有位置。
- 批量全失败不会伪造逐家已完成；重试/分片受预算约束。

### 20.3 统计与业务诊断

- 增加、减少、不变、零基线上升、降为零、UNKNOWN 均覆盖。
- Top 5+其他还原两期数量，其他百分比为汇总后计算。
- Code 与 Source 各自核对、不相加。
- 数量下降但贡献上升，正确解释分母影响。
- US×AutoUS 与 US×其他已知 Source 使用联合事实；UNKNOWN 不冒充其他。
- 只有独立分布时不声称联合关系。
- DD/SH/SC/NR/RQ 解释与业务规则一致，不指控个人、不宣称因果。
- Top 10 业务总结不泛化为全 Country 分布。

### 20.4 灵活分析与当前上下文

- 当前数量排名不使用历史贡献排名替代。
- Vendor 内占比、Top 10 合并占比和全 Country 占比分母正确。
- 组织过滤不放大行数，不隐式丢弃无映射 Vendor。
- Specialist 按实际目标 Vendor 查询，不以全国第一页判“没有”。
- 当前 detail 不被静默缩成仅高风险样本。
- 联系人按 Country 隔离、规则可追溯，仅展示；PO 配额在十家场景仍有效。

### 20.5 测试与输出

- “开始测试”在两国 NORMAL 时仍完成所有适用必需分析。
- 测试使用工作日日期对，不修改真实阈值和真实业务状态。
- 测试缺两期、过期、无正向 Vendor 均有明确结果和覆盖限制。
- 同一问题至少重复三次，指标、粒度、字段和顺序一致；自然语言解释允许措辞不同。
- 所选 Vendor 集合与报告集合相同，不以“其余类似”省略。
- 某检查未验证，不标 COMPLETE/PASS；报告生成不等于测试通过。

### 20.6 验证层次

1. 静态契约与文件一致性。
2. 固定数据数学与边界测试。
3. Atlas 正式 schema/config-check。
4. 真实 MCP 入口与 SQL 集成测试。
5. 真实 Agent 完整问答和最终报告验证。
6. 版本与部署回归。

前两层的 PASS 不能代替后四层。发布记录保留环境版本、输入范围、调用证据、核对结果和报告，不保存敏感凭据。
