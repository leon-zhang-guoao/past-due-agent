# PastDue 3.3.0：结构化读取与报告收敛

状态：**PENDING_LIVE_PILOT**。本地实现与打包，不代表部署或线上通过。

## 为什么调整

用户提供的 `chat/chat.md` 中，3.2报告接口可执行，但读取11条记录时每个
content-markdown被截为约500字符加省略号。减少列数仍截断；行完整不等于字段完整。
底层保留结果是否完整、handle异常根因尚未确认，不能写成已解决。
原始核对通过却被报告描述为“未通过”，属于解释错误，不能归咎于来源。

## 改动边界

- Prompt/Skill3.3默认 structured monitor/history/report/explore，不再依赖完整长文本。
- 复用现有API/计算SQL/业务指标3.1.0，不新增API、表、服务或线上脚本。
- 唯一Atlas执行配置变化：report-query/rows默认源页长200→1000，最大仍1000。
  标准上界为1条Country控制＋10×(1指标＋3维度×6摘要＋3检查)=221条。
  该界限来自现有标签/Top5+Other设计，不是实际平台测试。Explore等默认不改。
- Atlas publication3.3.0/revision4，旧3.2 blocks SQL/输出保持，标记兼容、不推荐默认。
- 生成器增加同一元数据步骤，防止下次生成恢复默认200/错误默认路由描述。
- 不修补旧block的格式/零桶诊断SQL，也不将其宣称已修复；新默认不使用它们。

## 分层责任

Atlas负责确定性指标、贡献排名、Top5/Other、signed totals和数量核对。
保留结果读取按真实handle、短字段、记录类型/稳定序号分页；无源SQL或指标重算。
Skill负责分析规格、绑定、读取覆盖、规则适用和固定输出模块。
Agent负责解释与格式化；不是确定性renderer，不具备独立输出验收能力。

## 两层读取

1. 源集合：从实际EQL分页获取完整记录，核对expected-record-count/ordinal。
2. 保留结果：同一个源页handle可以再按类型/序号分批读，所有分区并集覆盖源页。

两层分别记录；不能用完整预览冒充完整源集合。平台支持的LIMIT/OFFSET或WHERE
必须实际确认，示例不等于已支持。字段截断单独处理；长名称限制不应抹掉已核实数字，
身份字段截断则不能声称关联通过。没有完整读取路径时明确具体缺口，不自动逐Vendor查询。

## 输出与诊断

`report-format.md`唯一布局；EDN仅保留格式/绑定保护，不维护另一套布局。
国家指标→每国Vendor排行→国家Vendor总结→每家指标/Code/Source/变化诊断→覆盖率→跨国→缺失项。
所有选中Vendor均需完整单元或准确局部失败。自由问答只组合相关模块，不强制日报Top10。

0→0无风险提示；下降保留存量风险且说明改善；降为0仅该类清零；数量下降、贡献上升
解释分母影响。US规则必须联合Source，适用于US/CA等任意国家，融入国家总结，不新增列。
Other不猜组成。未适用不是失败。仅用真实桶事实，不照抄预生成诊断句。
